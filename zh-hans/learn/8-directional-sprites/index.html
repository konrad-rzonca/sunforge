Unity 八方向精灵：4、8 还是 16 个方向？

一套多方向精灵，是把同一个角色在每个可朝向的方向上各画一次。每个动画的每一帧都要为每个方向重画一遍，所以方向数量会让美术工作量和纹理内存同时成倍增加。

4、8 或 16 个方向

方向越少，精灵所指的方向与角色实际前进的方向偏差就越大。

以一个有三个动画、每个动画 8 帧、尺寸为 128 × 128 像素的角色为例。未压缩的 32 位 RGBA 每像素占 4 字节，因此一帧占 64 KiB。

BC7 等压缩格式每像素 8 位，占用只有上述数字的四分之一。

  • 4 个方向 适合网格移动和小尺寸像素画。
  • 8 个方向 与键盘移动角色的八个方向一致。
  • 16 个方向 适合可自由转向的对象，例如载具，或瞄准鼠标指针的角色。

翻转精灵，只画一半方向

两侧看起来相同的角色，只需要一侧的方向，再加上正上方和正下方。另一侧设置 Sprite Renderer 的 flipX 即可。这一设置只翻转渲染，所以碰撞器也需要翻转时，请使用负缩放。

翻转在两种情况下会显得不对：

  • 角色不对称。右手的剑会跑到左手。
  • 光照画进了精灵。画在左侧的高光会移到右侧，所以角色转身时，光会换到另一边。

侧视、俯视和等距精灵的摄像机角度

一套精灵还只针对一个摄像机俯角绘制，即摄像机高出地平线的角度。0 度时从侧面看角色，就像平台跳跃游戏。90 度时垂直向下看。显示角色面部的俯视游戏使用介于两者之间的角度。

在俯角 e 下，地面上的圆会画成椭圆，椭圆的高是宽的 sin(e) 倍；从一角正对着看的正方形瓦片会变成比例相同的菱形。30 度时 sin(e) 为 0.5，所以菱形的宽是高的两倍。这种 2:1 菱形就是大多数游戏所说的等距。Unity 等距 Tilemap 的默认 Cell Size（单元格大小）正是 x 1、y 0.5。

有两个角度常被混淆。2:1 瓦片的边在屏幕上约呈 26.6 度，而画出这些边的摄像机抬高了 30 度。真正的等距投影是第三种情况：摄像机抬高约 35.3 度，瓦片的边呈 30 度。

如何制作等距精灵

在 2:1 网格上绘制，或者用抬高 30 度的正交摄像机渲染 3D 模型，例如在 Blender 中渲染（步骤）。按相等的角度转动模型，摄像机和光源保持不动，这样每个方向的光都来自屏幕的同一侧。

在 Unity 中按方向选择精灵

  1. 为精灵表、动画剪辑和代码选定同一种方向顺序。下面的代码从朝右开始，按逆时针计数，与 Mathf.Atan2 测量角度的方式一致。
  2. 把朝向向量转换为索引：
    static int DirectionIndex(Vector2 facing, int count)
{
    float angle = Mathf.Atan2(facing.y, facing.x) * Mathf.Rad2Deg;
    int index = Mathf.RoundToInt(angle / (360f / count));
    return (int)Mathf.Repeat(index, count);
}
  3. 用以下三种方式之一显示该索引的精灵：
    • 不使用 Animator 时，从自己按方向和帧整理的精灵查找表中取值，设置 SpriteRenderer.sprite。
    • 使用 Animator 时，添加一个整数参数，为每个方向添加一个状态，并为每个过渡设置基于该参数的条件。用 SetInteger 设置该参数。
    • 使用 2D Simple Directional 混合树时，每个方向添加一个动画剪辑，并在 Pos X（位置 X）和 Pos Y（位置 Y）中输入该剪辑的方向，例如向右为 1 和 0。混合树会混合多个动作，而精灵不能一半是这张图、一半是那张图，所以要传入所选索引对应的方向，而不是原始输入。

陷阱

  • 方向顺序。 各精灵表的起始方向和排列方向各不相同。接入一张精灵表之前，先记下表中每一行对应代码中的哪个索引。
  • 两个方向之间的抖动。 摇杆停在两个方向的分界线上时，每帧都会切换精灵。保持当前方向，直到角度越过分界线一定余量，这里为 5 度：
    float step = 360f / count;
float angle = Mathf.Atan2(facing.y, facing.x) * Mathf.Rad2Deg;
if (Mathf.Abs(Mathf.DeltaAngle(current * step, angle)) > step * 0.5f + 5f)
    current = DirectionIndex(facing, count);

    向量接近零时跳过更新，这样角色会保持停下时的朝向。

  • 角度压缩。 在 2:1 等距游戏中，沿瓦片边行走的角色在屏幕上以 26.6 度移动，而不是 45 度，所以按屏幕向量选出的精灵常常是错的。先把向量的 y 除以 sin(e)，30 度时这会让 y 翻倍。
  • 轴心漂移。 轴心是精灵局部坐标的原点。在每个方向的每一帧中，都把轴心放在双脚之间的同一位置，否则角色转身时会发生位移。Sprite Editor 的 Automatic（自动）切分按透明度切割，每帧得到的矩形大小各异，内置的轴心选项会随姿势移动。请改为按网格切分，让角色在每个单元格中的位置相同。

用 Sun Forge 从 3D 模型烘焙各个方向

Sun Forge 是在 Unity 内完成这类渲染的 Unity 编辑器工具。Sun Forge 把 3D 模型或预制件连同动画剪辑一起烘焙成 2D 精灵预制件：每个方向一张精灵表，以及带动画器控制器的动画。

在烘焙窗口中，Directions 可设为 1 到 64，其中任何方向都可以关闭。Elevation Angle 的范围为 0 到 90 度，步长 0.25：0 为侧视，90 为垂直俯视，30 对应 2:1 菱形。

输出的都是标准 Unity 资产：精灵、精灵图集、动画剪辑、动画器控制器和预制件。精灵烘焙工具页面有一圈可以转动的烘焙精灵。

每次烘焙后，Bake 选项卡会显示纹理内存，方向越少，占用越少。以 Sun Forge Showcase 中的骑士为例：4 个动画共 968 个精灵，为 Windows、Mac 和 Linux 打包后占 81 MiB。
