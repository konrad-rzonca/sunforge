Unity の 8 方向スプライト: 4 方向か 8 方向か 16 方向か?

方向別のスプライトセットは、1 体のキャラクターを、向きうる方向ごとに 1 回ずつ描いたものです。すべてのアニメーションのすべてのフレームを方向ごとに描き直すため、方向の数に比例して、アートの量もテクスチャメモリも増えます。

4 方向、8 方向、16 方向

方向が少ないほど、スプライトが向いている方向と、キャラクターが実際に進む方向のずれが大きくなります。

例として、128 x 128 ピクセルで 8 フレームのアニメーションを 3 つ持つキャラクターを考えます。非圧縮の RGBA 32 bit は 1 ピクセルに 4 バイトを使うため、1 フレームは 64 KiB です。

BC7 などの圧縮フォーマットは 1 ピクセルあたり 8 ビットで、これらの数値の 4 分の 1 になります。

  • 4 方向は、グリッド上の移動や小さなドット絵に向いています。
  • 8 方向は、キーボードでキャラクターを動かせる 8 つの向きと一致します。
  • 16 方向は、乗り物やポインターに狙いを向けるキャラクターなど、自由に回転するものに向いています。

スプライトの反転で描く方向を半分に

左右どちらから見ても同じに見えるキャラクターなら、片側の方向に加えて、上向きと下向きだけを描けば済みます。反対側には Sprite Renderer の flipX を設定してください。反転するのは描画だけなので、コライダーも反転させる必要がある場合は負のスケールを使ってください。

反転すると不自然に見えるのは、次の 2 つの場合です。

  • キャラクターが左右非対称です。右手に持った剣が左手に移ります。
  • 光がスプライトに描き込まれています。左側に描いたハイライトが右側に移るため、キャラクターが向きを変えると光の当たる側が入れ替わります。

サイドビュー、見下ろし、アイソメトリック (クォータービュー) のスプライトのカメラ角度

スプライトセットは、1 つのカメラの俯角に合わせて描くものでもあります。俯角は、カメラを水平線からどれだけ上げるかを表す角度です。0 度ではプラットフォーマーのようにキャラクターを横から見ます。90 度では真下を見下ろします。顔が見える見下ろしのゲームは、その間の角度を使います。

俯角 e から見ると、地面の円は高さが幅の sin(e) 倍の楕円として描画され、角を手前に向けた正方形のタイルも同じ比率のひし形になります。30 度では sin(e) が 0.5 なので、ひし形の幅は高さの 2 倍です。この 2:1 のひし形が、ほとんどのゲームでアイソメトリックと呼ばれるものです。Unity のアイソメトリック Tilemap の Cell Size のデフォルト値 (x 1、y 0.5) も、この比率です。

よく混同される角度が 2 つあります。2:1 のタイルの辺は画面上で約 26.6 度傾いていて、それを描画するカメラの俯角は 30 度です。真のアイソメトリック投影は 3 つ目のケースで、カメラの俯角は約 35.3 度、タイルの辺の傾きは 30 度です。

アイソメトリックスプライトの作り方

2:1 のグリッドに沿って描くか、Blender などで、俯角 30 度の平行投影カメラから 3D モデルをレンダリングしてください (手順)。モデルを等間隔で回し、カメラとライトは動かさないでください。そうすると、どの方向でも光が画面の同じ側から当たります。

Unity で方向に合ったスプライトを選ぶ方法

  1. シート、クリップ、コードで使う方向の順番を 1 つに決めます。以下のコードは右向きから始まり、Mathf.Atan2 が角度を測るのと同じく反時計回りに数えます。
  2. 向きのベクトルをインデックスに変換します。
    static int DirectionIndex(Vector2 facing, int count)
{
    float angle = Mathf.Atan2(facing.y, facing.x) * Mathf.Rad2Deg;
    int index = Mathf.RoundToInt(angle / (360f / count));
    return (int)Mathf.Repeat(index, count);
}
  3. そのインデックスのスプライトを、次の 3 つのいずれかの方法で表示します。
    • Animator を使わない場合は、方向とフレームごとのスプライトをまとめた自作の表から SpriteRenderer.sprite を設定します。
    • Animator を使う場合は、整数のパラメーターと方向ごとのステートを追加し、各遷移にそのパラメーターの条件を設定します。値は SetInteger で設定します。
    • 2D Simple Directional ブレンドツリーを使う場合は、方向ごとに 1 つのクリップを追加し、その方向を Pos X (位置 X) と Pos Y (位置 Y) に入力します。右なら 1 と 0 です。ブレンドツリーは複数のモーションを混ぜますが、スプライトは 1 枚の絵の半分と別の絵の半分にはなれないため、生の入力ではなく、選んだインデックスの方向を渡してください。

落とし穴

  • 方向の順番。 シートによって、始まる方向も回る向きも異なります。シートを組み込む前に、各行がコードのどのインデックスに当たるかを書き出しておいてください。
  • 2 つの方向の間でのちらつき。 2 つの方向の境界線上にスティックを倒したままにすると、毎フレームスプライトが切り替わります。角度がその境界線をある程度 (ここでは 5 度) 越えるまでは、現在の方向を保ってください。
    float step = 360f / count;
float angle = Mathf.Atan2(facing.y, facing.x) * Mathf.Rad2Deg;
if (Mathf.Abs(Mathf.DeltaAngle(current * step, angle)) > step * 0.5f + 5f)
    current = DirectionIndex(facing, count);

    ベクトルがゼロに近いときは更新をスキップしてください。そうすると、キャラクターは止まったときの向きのままになります。

  • つぶれた角度。 2:1 のアイソメトリックゲームでは、タイルの辺に沿って歩くキャラクターは画面上で 45 度ではなく 26.6 度の方向に動くため、画面上のベクトルから選んだスプライトはよく間違ったものになります。先にベクトルの y を sin(e) で割ってください。30 度なら y が 2 倍になります。
  • ずれるピボット。 ピボットはスプライトのローカル座標の原点です。すべての方向のすべてのフレームで、足元の、両足の間の同じ位置に置いてください。そうしないと、向きを変えるときにキャラクターがずれます。Sprite Editor ウィンドウの Automatic (自動) スライスは透明度で切り分けるため、フレームごとに大きさの異なる矩形ができ、あらかじめ用意された位置のピボットがポーズに合わせて動いてしまいます。代わりにグリッドでスライスし、各セルの同じ位置にキャラクターを置いてください。

Sun Forge で 3D モデルから各方向をベイクする方法

Unity のエディターツールである Sun Forge は、このレンダリングを Unity の中で処理します。3D モデルまたはプレハブを、そのアニメーションクリップとともに 2D のスプライトプレハブにベイクします。方向ごとのスプライトシートと、アニメーターコントローラー付きのアニメーションが含まれます。

Bake Window では、Directions を 1 から 64 に設定でき、そのうちどの方向でもオフにできます。Elevation Angle は 0 から 90 度まで 0.25 度刻みで設定できます。0 はサイドビュー、90 は真下、30 は 2:1 のひし形です。

出力は Unity の標準アセットです。スプライト、スプライトアトラス、アニメーションクリップ、アニメーターコントローラー、プレハブが含まれます。スプライトベイカーのページでは、ベイクしたスプライトのリングを回して確かめられます。

Bake タブには、ベイクのたびにテクスチャメモリが表示され、方向を減らすほど少なくなります。目安として、Sun Forge のショーケースの騎士は 4 つのアニメーションで 968 枚のスプライトがあり、Windows、Mac、Linux 向けにパックすると 81 MiB です。
