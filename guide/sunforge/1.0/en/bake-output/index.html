What a bake writes

Every file a bake writes and where, how the output loads through Addressables, and what to commit.

On this page
  • Files
  • Addressables
  • Version Control

Files

A bake writes into <Output Root>/<Output Name>/. An archetype with a blank Output Root bakes into Output/<archetype> in the Sun Forge Folder, Assets/SunForge unless you change it in Project Settings > Sun Forge.

File What it is
<Name>.prefab The prefab to place in a scene
<Name>_BakedData.asset Everything the bake measured, which scripts read
<Name>_Controller.controller The Animator Controller, when the bake has animations and Animation Player (Advanced view) is Auto or Animator
<Name>_Dnn.png The rest pose, one sheet per direction. A bake writes these, and their shadows, only when no animation entry's Mode is Idle
<Name>_<Clip>_Dnn.png One sheet per animation and direction. <Clip> is the animation entry's output name, with _ for each dot. It also names the entry's Animator state
<Name>_Shadow_Dnn.png, <Name>_<Clip>_Shadow_Dnn.png Ground-projected shadows
<Name>_EllipseShadow_Dnn.png, <Name>_<Clip>_EllipseShadow_Dnn.png Ellipse shadows
<Name>_Particles_Dnn.png, <Name>_Particles_Controller.controller Particle flipbooks, and their controller when an Animator plays them: under Animator, or under Auto in a bake with animations
<sheet>_Normal.png, _MaskTex.png, _Emission.png, _Geometry.png, _CastHeight.png Extra textures beside a sheet
<Name>_Atlas.spriteatlasv2, _Shadow_Atlas, _Particles_Atlas Sprite atlases. With Bake Cast Height Texture (Advanced view) on, the ellipse shadows pack into _EllipseShadow_Atlas
<Name>_Atlas_2.spriteatlasv2, _Atlas_3 and so on, and the same for each atlas above More atlases of that kind, when one atlas would need more memory to pack than a 16 GB computer has free. A rebake that needs fewer deletes the rest, but keeps one you added your own sprites to, with yours alone
  • Dnn numbers a direction: D00 shows the model's back, and the numbers run clockwise. A direction an animation does not bake writes no file, so its number is skipped.
  • Each sheet holds only what its frames draw, so sheet sizes differ between animations.
  • A bake can write both shadow types. The prefab then shows the ground-projected shadow and keeps the ellipse one disabled. Shadows are baked, so moving the scene's sun never moves them.

A Body That Leaves The Ground

With Leaves The Ground on (Archetypes tab, PHYSICS, Advanced view), the prefab draws its body on a Body child, and its root keeps the collider, the movers and the shadows on the ground.

  • To change where the body sorts, set Order in Layer on the Sorting Group of the GroundSort child, which the Body child hangs from.
  • To change the body's height while the game runs, use a script (Scripting › Reading Baked Data).

Addressables

With Mark Addressable (Advanced view) on, a bake registers its prefab and its sprite atlases, each addressed by its path. A load by the label returns the atlases with the prefabs, so give the load the GameObject type.

  • A rebake keeps each entry's address and group, and every label you added. It replaces the label the last bake added with its own, and adds back an entry you removed.
  • Changing the archetype's Addressables Group (Advanced view) moves no entry already registered. Move the prefab and its atlases together in the Addressables Groups window.
  • After the output folder moves, whether a bake or you moved it, its entries keep their old paths as addresses until you change them.
  • While the atlases do not pack, if other Addressables content uses a baked sprite, mark that sprite's sheet and extra textures Addressable, so the build keeps one copy of each.

Version Control

Commit When
Your bake presets, and your Sun Forge Folder apart from its Output folder. It holds your archetype libraries, edited materials and lighting styles Always
The bake output, the Sun Forge Folder's Output folder included When scenes or prefabs reference baked assets, or you changed a baked file's settings, such as a platform override or an Addressables entry

A bake can recreate its output from the presets, so you can leave the output out if you load baked content only through Addressables. References to the recreated files break if the output folder was renamed or moved after its first bake.

With Unity's version control integration on, a bake checks out each output file it changes.
