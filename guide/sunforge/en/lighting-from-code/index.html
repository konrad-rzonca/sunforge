Lighting from code

Light a scene and set up its sprites from an editor script.

On this page
  • Preview A Setup
  • Give Sprites A Role
  • Press A Performance Button
  • Save And Tune A Style

An editor script can light a scene in a style, set your sprites up as Set Up for Lighting does, and do what Fix All does:

using System.Collections.Generic;
using KonradRzonca.SunForge;
using KonradRzonca.SunForge.Editor;
using UnityEditor;
using UnityEditor.SceneManagement;
using UnityEngine;
using UnityEngine.Rendering;

SunForgeSceneLighting.SetUp(SunForgeShippedLightingStyle.Regular);

Object[] art = { AssetDatabase.LoadAssetAtPath<DefaultAsset>("Assets/Art") };
foreach (string line in SunForgeSceneLighting.SetUpSprites(art))
    Debug.Log(line);

SunForgeSceneLighting.FixAll();

// On the Universal Renderer, the sort that Fix All skips. A Custom Axis is a choice of yours, so keep it.
if (GraphicsSettings.transparencySortMode != TransparencySortMode.CustomAxis)
{
    GraphicsSettings.transparencySortMode = TransparencySortMode.CustomAxis;
    GraphicsSettings.transparencySortAxis = new Vector3(0f, 1f, 0f);
}

IReadOnlyList<string> left = SunForgeSceneLighting.Check();
foreach (string message in left)
    Debug.LogWarning(message);

EditorSceneManager.SaveOpenScenes();
AssetDatabase.SaveAssets();
  • SetUp(SunForgeShippedLightingStyle.Regular, SunForgeLightingStyleVariant.Indoor) sets the scene up in Regular's Indoor variant.
  • For art drawn from the side, as a platformer's is, set ViewElevationDegrees of the Lighting Setup that SetUp returns to 0 before you set the sprites up.
  • SetUpSprites does what Set Up for Lighting does when you click Apply, and returns lines to show or log: what it changes and saves, what each sprite is set up as, the sprites it leaves alone and the pivots it moves. A folder brings every sprite texture and prefab under it, a GameObject every sprite under it, and a sprite every renderer that shows it. It saves at once the sprites whose pivots move, the prefabs, the scenes that are not open and each open scene whose placed art a pivot move corrects, and Undo cannot take these saves back. It adds no Lighting Setup and sets no Art View, so call it after SetUp and the view: the view decides how each sprite is set up, and a side view moves no pivot.
  • FixAll applies every fix that Fix All applies and opens no window. It leaves each fix that opens Set Up for Lighting: set those sprites up with SetUpSprites. It returns what is left: what only you can fix, each fix Fix All skips because it changes a choice of yours, and each finding to fix with SetUpSprites. Call it once the scene has its sprites, and again after you add more: it adds what they need, such as a Cast Shadow Field for a sprite that casts a shadow. Check returns what is left and changes nothing.
  • A camera that is already loaded keeps its own sort until its scene loads again, and a Scene view keeps its sort until you open it again. To sort them now, also set transparencySortMode and transparencySortAxis on each loaded camera and on each camera SceneView.GetAllSceneCameras() returns.
  • The other changes are in the open scenes and the project's assets in memory. Save both before the script ends, as the last two lines do.

Preview A Setup

To show what a setup changes before it saves anything, preview it with the arguments you apply it with. PreviewSpriteSetup returns the lines SetUpSprites returns, and changes nothing:

Object[] art = { AssetDatabase.LoadAssetAtPath<DefaultAsset>("Assets/Art") };
foreach (string line in SunForgeSceneLighting.PreviewSpriteSetup(art))
    Debug.Log(line);

if (EditorUtility.DisplayDialog("Set Up for Lighting", "Set up the sprites the Console lists?", "Set Up", "Cancel"))
{
    SunForgeSceneLighting.SetUpSprites(art);
    EditorSceneManager.SaveOpenScenes();
}
  • To keep the pivots where they are, as Keep these pivots does, pass keepPivots: true to both calls. Later runs keep the choice.

Give Sprites A Role

To give sprites a role, as the dropdown beside each sprite does, pass it. Set up the floor first, so the other sprites are set up around it:

var floor = AssetDatabase.LoadAssetAtPath<Sprite>("Assets/Art/Floor.png");
SunForgeSceneLighting.SetUpSprites(new Object[] { floor }, SunForgeSpriteRole.Ground);
SunForgeSceneLighting.SetUpSprites(new Object[] { AssetDatabase.LoadAssetAtPath<DefaultAsset>("Assets/Art") });
EditorSceneManager.SaveOpenScenes();
  • The role goes to each Sprite Renderer you name, the Sprite Renderer on each GameObject you name, every renderer that shows a sprite or sprite texture you name, and for a folder, each sprite texture under it and the Sprite Renderer at the root of each prefab under it. A placed copy of a prefab takes it in its prefab. Where the window would ask about a sprite, such as one that may be ground, the call sets it up on the role the window first shows for it, and the lines it returns ask the question. To answer before anything saves, preview first, then set that sprite up with the role you choose, as the code above does for the floor.
  • Where the window would ask you to save a prefab open in Prefab Mode, or a scene that has no file, or where Set Up for Lighting cannot run, such as in Play mode, or where version control or a read-only file stops it, the call throws InvalidOperationException and nothing changes. Where a file does not save or Unity throws once the setup has started, it throws IOException, whose message says what is not set up.

Press A Performance Button

A script presses a Performance button with ApplyPerformance, which returns each setting it changed:

var lit = Object.FindAnyObjectByType<SunForgeLightingSetup>();
SunForgeSceneLighting.ApplyPerformance(lit, SunForgeLightingPerformanceButton.Balanced);
EditorSceneManager.SaveOpenScenes();

Save And Tune A Style

A script can save a style of your own and tune it as Look does (Tune a style). This one saves the scene's look and turns Pixel Outline on:

var setup = Object.FindAnyObjectByType<SunForgeLightingSetup>();
SunForgeLightingStyle style = SunForgeSceneLighting.SaveAsNewStyle(setup, "Assets/Lighting/My Style.asset");
IReadOnlyList<Material> materials = SunForgeLightingStyleEditing.EnsureOwnMaterials(style);

SunForgeLightingStyleSetting row = SunForgeLightingStyleSettings.Find("_SFPixelOutline");
foreach (Material material in materials)
{
    if (!material.HasProperty(row.Name))
        continue;

    Undo.RecordObject(material, "Set Pixel Outline");
    material.SetFloat(row.Name, 1f);
    if (row.Keyword != null)
        material.EnableKeyword(row.Keyword);
}

EditorSceneManager.SaveOpenScenes();
AssetDatabase.SaveAssets();
  • SaveAsNewStyle throws where a file is at the path, unless you pass overwrite: true and the file is a lighting style. To tune a style you saved before, load it with AssetDatabase.LoadAssetAtPath<SunForgeLightingStyle> instead.
  • For the post-processing, EnsureOwnProfile gives the style its own copy of its profile and returns it.
  • SunForgeLightingStyleSettings.MaterialProperties lists every row with the Name of its property, its Tooltip and its Group. A row's label in Look is the property's description in the material's shader: shader.GetPropertyDescription(shader.FindPropertyIndex(row.Name)).
  • A slider's limits are the shader's, from shader.GetPropertyRangeLimits. SetFloat does not keep a value inside them.
  • A row with a Keyword needs both: set the property, and turn the keyword on with EnableKeyword or off with DisableKeyword. A row with a Switch shows only while the row that name gives is on, as Pixel Outline Color does under Pixel Outline.
  • Undo.RecordObject before each change makes the scene draw it at once. Without it, call Publish on the Lighting Setup.
  • The BakedArt rows are not in Look: set one on the material it is for. Leave the Orientation rows as they are.
