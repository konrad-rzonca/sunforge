8-directional sprites in Unity: 4, 8 or 16?

A directional sprite set is one character drawn once for each direction it can face. Every frame of every animation is drawn again for every direction, so the number of directions multiplies both the art and the texture memory.

4, 8 or 16 directions

The fewer directions there are, the further a sprite points away from where the character is heading.

Take a character with three animations of 8 frames each, at 128 by 128 pixels. Uncompressed RGBA 32 bit takes 4 bytes per pixel, so one frame takes 64 KiB.

A compressed format such as BC7, at 8 bits per pixel, takes a quarter of these figures.

  • 4 directions fit movement on a grid and small pixel art.
  • 8 directions match the eight ways a keyboard moves a character.
  • 16 directions fit what turns freely, such as a vehicle or a character that aims at the pointer.

Flip sprites to draw half the directions

A character that looks the same from both sides needs only the directions on one side, plus straight up and straight down. For the other side, set the Sprite Renderer's flipX. It flips only the rendering, so use a negative scale when colliders must flip too.

Flipping looks wrong in two cases:

  • The character is asymmetric. A sword in the right hand moves to the left hand.
  • Light is drawn into the sprite. A highlight painted on the left moves to the right, so the light changes sides when the character turns.

The camera angle for side view, top-down and isometric sprites

A sprite set is also drawn for one camera elevation: how far the camera is raised above the horizon. At 0 degrees it sees the character from the side, as in a platformer. At 90 it looks straight down. Top-down games that show faces use an angle in between.

From an elevation of e, a circle on the ground is drawn as an ellipse whose height is sin(e) times its width, and a square tile seen corner first becomes a diamond with the same proportions. At 30 degrees sin(e) is 0.5, so the diamond is twice as wide as it is tall. That 2:1 diamond is what most games call isometric. It is the default Cell Size of Unity's isometric Tilemap, x 1 and y 0.5.

Two angles are often mixed up. The edges of a 2:1 tile run at about 26.6 degrees on the screen, and the camera that draws them is raised 30 degrees. True isometric projection is a third case: its camera is raised about 35.3 degrees, and its tile edges run at 30.

How to make isometric sprites

Draw them on a 2:1 grid, or render a 3D model with an orthographic camera raised 30 degrees, in Blender for example (the steps). Turn the model in equal steps and keep the camera and the light still, so the light comes from the same side of the screen in every direction.

Pick the sprite for a direction in Unity

  1. Choose one direction order for your sheets, clips and code. The code below starts at facing right and counts counterclockwise, as Mathf.Atan2 measures angles.
  2. Turn the facing vector into an index: 
    static int DirectionIndex(Vector2 facing, int count)
{
    float angle = Mathf.Atan2(facing.y, facing.x) * Mathf.Rad2Deg;
    int index = Mathf.RoundToInt(angle / (360f / count));
    return (int)Mathf.Repeat(index, count);
}
  3. Show the sprites of that index, in one of three ways:
    • Without an Animator, set SpriteRenderer.sprite from your own table of sprites by direction and frame.
    • With an Animator, add an integer parameter and a state for each direction, and give each transition a condition on the parameter. Set it with SetInteger.
    • With a 2D Simple Directional blend tree, add one clip per direction and type its direction into Pos X and Pos Y, such as 1 and 0 for right. A blend tree mixes several motions, and a sprite cannot be half of one picture and half of another, so pass the direction of the index you picked, not the raw input.

Traps

  • Direction order. Sheets start at different directions and run different ways. Before you wire a sheet up, write down which of your indexes each of its rows is.
  • Jitter between two directions. A stick held on the line between two directions switches sprites every frame. Keep the current direction until the angle is past that line by a margin, here 5 degrees: 
    float step = 360f / count;
float angle = Mathf.Atan2(facing.y, facing.x) * Mathf.Rad2Deg;
if (Mathf.Abs(Mathf.DeltaAngle(current * step, angle)) > step * 0.5f + 5f)
    current = DirectionIndex(facing, count);

    When the vector is near zero, skip the update, so the character keeps facing the way it stopped.

  • Squashed angles. In a 2:1 isometric game, a character that walks along a tile edge moves at 26.6 degrees on the screen, not 45, so a sprite picked from the screen vector is often the wrong one. Divide the vector's y by sin(e) first, which doubles it at 30 degrees.
  • Drifting pivots. The pivot is where a sprite's local coordinates start. Put it at the same place between the feet in every frame of every direction, or the character shifts as it turns. The Sprite Editor's Automatic slicing cuts by transparency, so each frame gets a rectangle of its own size, and a preset pivot moves with the pose. Slice by grid instead, with the character at the same place in each cell.

Bake the directions from a 3D model with Sun Forge

Sun Forge is a Unity editor tool that does this rendering inside Unity. It bakes a 3D model or prefab, with its animation clips, into a 2D sprite prefab: a sprite sheet for each direction, and the animations with an Animator Controller.

In the Bake Window, you set Directions from 1 to 64 and can switch off any of them. Elevation Angle goes from 0 to 90 degrees in steps of 0.25: 0 for a side view, 90 for straight down, and 30 for the 2:1 diamond.

The output is standard Unity assets: sprites, sprite atlases, animation clips, an Animator Controller and a prefab. The sprite baker's page has a ring of baked sprites you can turn.

The Bake tab shows the texture memory after each bake, and fewer directions take less. For scale, the knight in Sun Forge's showcase has 968 sprites over 4 animations and takes 81 MiB, packed for Windows, Mac and Linux.
