Make 2D sprites look 3D with Unity normal maps

A sprite is a flat picture, so a light has no form to fall across. A normal map gives it one: for each pixel, it holds the direction that part of the surface faces. With one, a torch to the left of a character lights its left side, and the shading moves when the torch moves.

Sprite Lit and Light 2D: how Unity lights a sprite

Unity's 2D lights are part of the Universal Render Pipeline (URP) and work when the project uses its 2D Renderer. There, a sprite you drag into the Scene view gets the Sprite-Lit-Default material, which 2D lights light. A sprite with Sprite-Unlit-Default ignores them.

To add a light, right-click in the Hierarchy, choose Light and pick a 2D light: Spot, Freeform, Sprite or Global. A Global light lights every sprite equally. Without a normal map, the others light a sprite like a lamp over a paper cutout: brighter inside the light's shape, with no shading on the art itself.

What a sprite normal map stores

A normal map is a texture that lines up with the sprite's texture. Red holds how far each pixel's surface leans right, green how far it leans up, and blue how much it faces the viewer. A pixel that faces the viewer squarely is the light blue #8080FF.

Add a normal map to a sprite in Unity

  1. Import the normal map and set its Texture Type to Normal map in the Inspector.
  2. Select the sprite's texture, open the Sprite Editor and choose Secondary Textures from its dropdown.
  3. Click +, pick _NormalMap in the Name dropdown, assign your normal map and click Apply.
  4. Check that the sprite's Sprite Renderer uses Sprite-Lit-Default, or another material that reads a normal map.
  5. Select the Light 2D. Under Normal Maps, set Quality to Fast or Accurate.

A light ignores normal maps until you do step 5. A Global light has no such setting, so the scene needs a Spot, Freeform or Sprite light to show any shading. A lower Distance in the same section brings the light closer to the sprite, so the detail shows more.

A shader of your own can start from Assets > Create > Shader Graph > URP > Sprite Lit Shader Graph, which has a Normal (Tangent Space) input.

The mask texture, _MaskTex

A sprite can have a second secondary texture, _MaskTex. Import it with Texture Type at Default and sRGB (Color Texture) off.

A mask says where a light may fall: a light whose Blend Style is Multiply with Mask (R) or Additive with Mask (R) lights only the pixels where the mask's red channel is above 0. In the 2D Renderer asset, each blend style can read green, blue or alpha instead. Use it for a rim light, or for a glint on armor and nowhere else.

Where normal maps come from

  • Painted by hand. You paint the direction colors over the sprite from a normal map palette. Krita has a brush for it. An animated character needs a map for every frame.
  • Generated from the sprite. Paint a grayscale height map, whiter where the surface is higher, and import it with Texture Type at Normal map and Create from Grayscale on. Tools that work from the drawing alone guess the form, mostly by rounding the outline.
  • Rendered from a 3D model. If the sprite is a render of a 3D model, render the model's normals from the same camera, and every frame has a map that matches it. Blender's Normal pass holds directions in world space, so turn them to the camera's view before you save them.

What a normal map cannot do alone

  • Metal and smoothness. Unity's manual says its 2D lighting is not physically based. Sprite-Lit-Default reads a color texture, a mask and a normal map, and none of them says how shiny a pixel is, so steel and cloth take the light the same way. A masked light placed by hand can fake a glint.
  • Sprites that shadow each other. A Shadow Caster 2D takes its shape from an outline: the sprite's Custom Outline, a collider or a shape you draw. It has the sprite's edge, not how tall each part stands. Unity's Happy Harvest sample draws the shadows under its trees as stretched sprites instead. Shadows for 2D and top-down sprites has each way.

Both need more data per pixel: how metallic and smooth the surface is, and how high it stands.

Why a Unity sprite normal map does not work

If the light changes nothing at all, start with the checks for 2D lights that do not work. These are the traps of the map itself:

  • The texture type. A normal map left at Sprite (2D and UI) shades wrong: the dark side stays put when the light moves. Set Texture Type to Normal map, with Create from Grayscale off unless the file is a height map.
  • A flipped green channel. Unity expects green to mean up, the convention known as Y+ or OpenGL. A map made for the other convention looks lit from below when the light is above. Turn on Flip Green Channel in the texture's import settings.
  • Flipped sprites. The Sprite Renderer's Flip X flips only what is drawn. A sprite turned 180 degrees around Y lights wrong, which Unity treats as designed. If you flip with a negative Scale X, put a light above the sprite and check that its top edges are the lit ones.
  • Sprite atlases. A Sprite Atlas combines its sprites' secondary textures into textures of their own. Give every sprite in an atlas the same number of secondary textures, or the combined ones can hold a lot of empty space. If another tool packs your sheets, it must pack the normal maps in the same layout, because Unity reads both with the same UVs.

Sun Forge: normal, mask, Geometry and emission textures for each sprite

Sun Forge, a Unity editor tool, takes the third route inside Unity. A bake turns a 3D model or prefab into a 2D sprite prefab, with a sprite sheet for each direction. Each sheet gets a normal, a mask and a Geometry texture beside its color, and an emission texture when the bake has Emission on.

  • The mask holds metal in red, smoothness in green and ambient occlusion in blue.
  • The Geometry texture holds each texel's height above the sprite's pivot, which lets sprites cast shadows on each other.

Its lighting package, Sun Forge 2D Lighting, reads these textures. Cast shadows climb the sprites standing in them, as high as what casts them.

The lighting also lights sprites you drew. Select them, right-click and choose Sun Forge > Set Up for Lighting. A normal map of your own gives them form, and without one a sprite is lit as a flat surface. You pick the colors that glow and the colors that shine like metal, and Sun Forge writes their glow and metal textures.

Sun Forge needs Unity 6.3 LTS (6000.3.28f1 or newer) or Unity 6.6, and URP with the 2D Renderer or the Universal Renderer. The baker and the lighting each work without the other: see the sprite baker and the lighting.
