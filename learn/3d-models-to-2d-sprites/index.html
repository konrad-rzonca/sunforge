Turning 3D models into 2D sprites in Unity

A 2D sprite made from a 3D model is a render of the model through a fixed camera, saved with a transparent background. An animated character is many such renders: one per frame, per animation, per direction. You render the frames, slice them into sprites, build animation clips and pack the textures.

How to make 2D sprites from 3D models in Blender

  1. Set the camera's type to Orthographic, so the model keeps its size at any distance. Orthographic Scale sets how large it is in the picture.
  2. Under Film in the render settings, turn on Transparent.
  3. Set the output's color to RGBA, in a format such as PNG, to keep the alpha channel.
  4. Render the animation as an image sequence. For another direction, turn the model or the camera and render again.

Import the PNG files as they are, one sprite per file, or join them into a sheet first.

Rendering a 3D model to sprites in Unity

  1. Add a camera and set Projection to Orthographic. Its Size is half the height of the view in world units.
  2. Set Background Type to Solid Color and the alpha of the Background color to 0.
  3. Create a Render Texture (Assets > Create > Rendering > Render Texture) whose color format has an alpha channel, and assign it to the camera's Output Texture.
  4. In URP, turn off Post Processing on the camera or turn on Alpha Processing in the URP Asset. Otherwise post-processing replaces alpha with 1.
  5. For each frame, pose the model with clip.SampleAnimation(model, time) and save the picture from an editor script:
static void SaveFrame(Camera camera, RenderTexture target, string path)
{
    camera.targetTexture = target;
    camera.Render();

    RenderTexture previous = RenderTexture.active;
    RenderTexture.active = target;
    var frame = new Texture2D(target.width, target.height, TextureFormat.RGBA32, false);
    frame.ReadPixels(new Rect(0, 0, target.width, target.height), 0, 0);
    frame.Apply();
    RenderTexture.active = previous;

    System.IO.File.WriteAllBytes(path, ImageConversion.EncodeToPNG(frame));
    Object.DestroyImmediate(frame);
}

The Render Texture and the Texture2D must have the same format. In a project in the Linear color space, pick a Render Texture format that ends in _SRGB, or the saved colors come out dark.

Slicing a sprite sheet in the Sprite Editor

  1. Check that the 2D Sprite package is installed.
  2. Select the image, set Texture Type to Sprite (2D and UI) and Sprite Mode to Multiple, and select Apply.
  3. Open the Sprite Editor and its Slice menu. Choose Grid By Cell Size for frames of equal size, or Grid By Cell Count for a known number of rows and columns.
  4. Set the Pivot, select Slice, then Apply.

Animation clips and an Animator Controller from the frames

  1. Drag the first sprite into the scene, which creates a GameObject with a Sprite Renderer.
  2. With that GameObject selected, select Create in the Animation window and save the clip. Unity creates an Animator Controller with the clip as its default state and adds an Animator to the GameObject.
  3. Key the Sprite Renderer's sprite, one sprite per frame.
  4. For each further animation, choose Create New Clip in the Animation window's clip menu, then add transitions between the clips in the Animator Controller.

For many clips, script this step: Unity's reference for AnimationClip has an example that builds a clip from the sprites selected in the Project window.

The traps

Pixels per unit

Pixels Per Unit is how many pixels of the sprite image cover one unit of world space. Pick the value you will import with, and make the Render Texture 2 x Size x Pixels Per Unit pixels high: 192 pixels for a Size of 1.5 at 64 Pixels Per Unit. The sprite is then as tall in the 2D scene as the model was. Use one value for every sprite, or some look sharper than others.

Pivots and framing

The pivot is the point of the image where the sprite's local coordinates start. For a character, put it at the feet, on the same pixel in every frame. For that, render every frame of every animation from one camera position, at one Size and one resolution, wide enough for the widest pose. Then slice by grid and set one pivot for all. The Automatic slice cuts on transparent pixels, so each frame gets its own rectangle, a pivot such as Bottom lands on a different point of the body in each, and the character jitters.

Premultiplied alpha and edge halos

When transparent geometry is blended into a Render Texture, the texture stores each color already multiplied by its alpha. A material with traditional transparency (Blend SrcAlpha OneMinusSrcAlpha) multiplies by alpha again, and see-through pixels turn dark. Divide the color by the alpha before you save the PNG, or use a shader that blends premultiplied color (Blend One OneMinusSrcAlpha).

Texture filtering mixes each edge pixel with the transparent pixels beside it. Turn on Alpha Is Transparency in the texture's import settings: Unity then dilates the color channels, which avoids filtering artifacts at the edges.

Texture size and atlas packing

Eight directions and three animations of 16 frames each, at 256 by 256 pixels, are 384 frames, about 25 million pixels, or 96 MiB uncompressed. Half the Pixels Per Unit takes a quarter of that.

At import, Unity scales a texture larger than its Max Size down to that size, so raise Max Size for a large sheet or split it by animation. Then pack the sprites into a Sprite Atlas (Assets > Create > 2D > Sprite Atlas), which combines textures into one, so Unity can draw all its sprites in one draw call.

Lighting baked into the color, or normal maps

Light in the render becomes part of the sprite's color: a knight lit from the left stays lit from the left beside a torch on its right. For light that changes in the game, render the color under even light, and render a normal map of the same frames through the same camera. In the Sprite Editor, add it as a secondary texture named _NormalMap, use a material such as Sprite-Lit-Default, and under Normal Maps on the 2D light, set Quality to Fast or Accurate. The normal map must line up with the sprite texture, because Unity samples both with the same UV coordinates. Sprite normal maps in Unity has the steps and the traps.

A 3D to 2D sprite converter inside Unity: Sun Forge

Sun Forge is the sprite baker this site is about. It bakes in the Unity editor, from its Bake Window or from editor code. A bake takes a model or a prefab with its animation clips and particle systems, in its own materials, Shader Graphs included.

A bake writes a 2D sprite prefab: a sprite sheet for each direction, animations with an Animator Controller, lighting textures, shadows, a collider and gameplay components.

  • Camera. The bake camera looks at any angle from 0 to 90 degrees: a side view, straight down, and every angle between, isometric included. A bake writes 1 to 64 directions, and how many a game needs is an article of its own.
  • Resolution and memory. A new bake is at 96 Pixels Per Unit. After each bake, the Bake tab shows the texture memory its output takes.
  • Light. Each sheet has a normal, a mask and a Geometry texture beside its color, and Sun Forge 2D Lighting reads them, so the sun and the lights change live. A bake writes only the textures whose switches are on, and can give its prefab Unity's default sprite material.

Sun Forge needs Unity 6.3 LTS (6000.3.29f1 or newer) through Unity 6.6, and URP with the 2D Renderer or the Universal Renderer. On the Built-in Render Pipeline or HDRP, use the steps above. The sprite baker's page shows each part of a bake.
