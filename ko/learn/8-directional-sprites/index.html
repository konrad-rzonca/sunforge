유니티 8방향 스프라이트: 4, 8, 16방향 중 어느 쪽?

방향별 스프라이트 세트는 캐릭터 하나를 그 캐릭터가 바라볼 수 있는 방향마다 한 번씩 그린 것입니다. 모든 애니메이션의 모든 프레임을 방향마다 다시 그리므로, 방향 수에 비례해 아트 작업과 텍스처 메모리가 모두 늘어납니다.

4방향, 8방향, 16방향

방향이 적을수록 스프라이트가 가리키는 방향이 캐릭터가 실제로 나아가는 방향에서 더 많이 벗어납니다.

128 x 128픽셀 크기에 애니메이션 3개가 각각 8프레임인 캐릭터를 예로 듭니다. 압축하지 않은 RGBA 32비트는 픽셀당 4바이트이므로 프레임 하나가 64KiB를 차지합니다.

방향최대 오차프레임비압축뒤집으면 그릴 방향
445°966MiB3
822.5°19212MiB5
1611.25°38424MiB9

픽셀당 8비트인 BC7 같은 압축 포맷은 이 수치의 4분의 1을 차지합니다.

  • 4방향은 그리드 위의 이동과 작은 픽셀 아트에 맞습니다.
  • 8방향은 키보드로 캐릭터를 움직이는 여덟 방향과 일치합니다.
  • 16방향은 탈것이나 포인터를 조준하는 캐릭터처럼 자유롭게 도는 대상에 맞습니다.

스프라이트를 뒤집어 방향을 절반만 그리기

양쪽에서 똑같아 보이는 캐릭터는 한쪽의 방향과 바로 위쪽, 바로 아래쪽 방향만 있으면 됩니다. 반대쪽은 Sprite Renderer 컴포넌트의 flipX 값을 설정하세요. 이 값은 렌더링만 뒤집으므로, 콜라이더도 함께 뒤집어야 한다면 음수 스케일을 쓰세요.

뒤집기가 어색해 보이는 경우는 두 가지입니다:

  • 캐릭터가 비대칭입니다. 오른손의 검이 왼손으로 옮겨 갑니다.
  • 빛이 스프라이트에 그려져 있습니다. 왼쪽에 칠한 하이라이트가 오른쪽으로 옮겨 가므로, 캐릭터가 돌 때 빛이 반대쪽으로 바뀝니다.

사이드 뷰, 탑다운, 아이소메트릭(쿼터뷰) 스프라이트의 카메라 각도

스프라이트 세트는 카메라 고도각 하나에 맞춰 그립니다. 카메라 고도각은 카메라가 지평선에서 얼마나 높이 올라가 있는지를 나타냅니다. 0도에서는 플랫포머처럼 캐릭터를 옆에서 봅니다. 90도에서는 바로 아래를 내려다봅니다. 얼굴을 보여 주는 탑다운 게임은 그 사이의 각도를 씁니다.

고도각 e에서 보면 지면의 원은 높이가 너비의 sin(e)배인 타원이 되고, 꼭짓점이 앞을 향한 정사각형 타일은 같은 비율의 마름모가 됩니다. 30도에서 sin(e) 값은 0.5이므로 마름모의 너비는 높이의 두 배입니다. 대부분의 게임이 아이소메트릭이라고 부르는 것이 이 2:1 마름모입니다. Unity의 아이소메트릭 Tilemap에서 기본 Cell Size 값인 x 1, y 0.5도 이 비율입니다.

두 각도는 자주 혼동됩니다. 2:1 타일의 변은 화면에서 약 26.6도로 기울어 있고, 이 타일을 그리는 카메라는 30도 올라가 있습니다. 진짜 아이소메트릭 투영은 세 번째 경우입니다. 카메라가 약 35.3도 올라가 있고, 타일의 변은 30도로 기울어 있습니다.

아이소메트릭 스프라이트를 만드는 방법

2:1 그리드에 그리거나, 블렌더 등에서 30도 올린 직교 카메라로 3D 모델을 렌더하세요(단계 참조). 모델은 같은 각도씩 돌리고 카메라와 광원은 고정하세요. 그래야 모든 방향에서 빛이 화면의 같은 쪽에서 들어옵니다.

Unity에서 방향에 맞는 스프라이트 고르기

  1. 시트, 클립, 코드에 쓸 방향 순서를 하나로 정합니다. 아래 코드는 Mathf.Atan2 메서드가 각도를 재는 방식대로, 오른쪽을 바라보는 방향에서 시작해 반시계 방향으로 셉니다.
  2. 바라보는 방향 벡터를 인덱스로 바꿉니다:
    static int DirectionIndex(Vector2 facing, int count)
{
    float angle = Mathf.Atan2(facing.y, facing.x) * Mathf.Rad2Deg;
    int index = Mathf.RoundToInt(angle / (360f / count));
    return (int)Mathf.Repeat(index, count);
}
  3. 다음 세 가지 방법 중 하나로 그 인덱스의 스프라이트를 표시합니다:
    • Animator 컴포넌트 없이 쓰려면 방향과 프레임별 스프라이트 표를 직접 만들고, 그 표에서 SpriteRenderer.sprite 값을 설정합니다.
    • Animator 컴포넌트를 쓴다면 정수 파라미터 하나와 방향마다 상태를 하나씩 추가하고, 각 전환에 그 파라미터의 조건을 지정합니다. 파라미터 값은 SetInteger 메서드로 설정합니다.
    • 2D Simple Directional 블렌드 트리를 쓴다면 방향마다 클립을 하나씩 추가하고 Pos X(X 위치) 필드와 Pos Y(Y 위치) 필드에 그 방향을 입력합니다. 예를 들어 오른쪽은 1과 0입니다. 블렌드 트리는 여러 모션을 섞지만 스프라이트는 반은 한 그림, 반은 다른 그림일 수 없으므로, 입력값을 그대로 넘기지 말고 고른 인덱스의 방향을 넘깁니다.

함정

  • 방향 순서. 시트마다 시작하는 방향과 도는 방향이 다릅니다. 시트를 코드에 연결하기 전에 시트의 각 행이 직접 정한 인덱스 중 어느 것인지 적어 두세요.
  • 두 방향 사이의 떨림. 두 방향의 경계선에 스틱을 두면 매 프레임 스프라이트가 바뀝니다. 각도가 경계선을 일정한 여유(여기서는 5도)만큼 넘어설 때까지 현재 방향을 유지하세요:
    float step = 360f / count;
float angle = Mathf.Atan2(facing.y, facing.x) * Mathf.Rad2Deg;
if (Mathf.Abs(Mathf.DeltaAngle(current * step, angle)) > step * 0.5f + 5f)
    current = DirectionIndex(facing, count);

    벡터가 0에 가까우면 업데이트를 건너뛰세요. 그러면 캐릭터가 멈춰도 바라보는 방향을 그대로 유지합니다.

  • 눌린 각도. 2:1 아이소메트릭 게임에서 타일의 변을 따라 걷는 캐릭터는 화면에서 45도가 아니라 26.6도로 움직이므로, 화면 벡터로 스프라이트를 고르면 잘못된 스프라이트가 나오는 경우가 많습니다. 먼저 벡터의 y 값을 sin(e) 값으로 나누세요. 30도에서는 y 값이 두 배가 됩니다.
  • 어긋나는 피벗. 피벗은 스프라이트의 로컬 좌표가 시작되는 곳입니다. 모든 방향의 모든 프레임에서 피벗을 두 발 사이의 같은 위치에 두세요. 그러지 않으면 캐릭터가 돌 때 위치가 어긋납니다. 스프라이트 에디터에서 Automatic(자동) 옵션으로 분할하면 투명도를 기준으로 자르므로 프레임마다 크기가 다른 사각형이 생기고, 미리 정한 피벗이 자세에 따라 움직입니다. 대신 그리드로 분할하고, 캐릭터를 각 셀의 같은 위치에 두세요.

Sun Forge로 3D 모델에서 방향별 스프라이트 베이크하기

Sun Forge는 이 렌더링을 Unity 에디터 안에서 하는 툴입니다. 3D 모델이나 프리팹을 애니메이션 클립과 함께 2D 스프라이트 프리팹으로 베이크하며, 프리팹에는 방향마다 스프라이트 시트, 애니메이션과 애니메이터 컨트롤러가 있습니다.

Bake Window에서 Directions 필드를 1~64로 설정하고, 필요 없는 방향은 끌 수 있습니다. Elevation Angle 필드는 0~90도 사이에서 0.25도 단위로 정합니다. 0은 사이드 뷰, 90은 바로 위에서 내려다보는 각도, 30은 2:1 마름모입니다.

출력은 스프라이트, 스프라이트 아틀라스, 애니메이션 클립, 애니메이터 컨트롤러, 프리팹으로, 모두 표준 Unity 에셋입니다. 스프라이트 베이커 페이지에서 베이크된 스프라이트로 된 링을 돌려 볼 수 있습니다.

Bake 탭에는 베이크할 때마다 텍스처 메모리가 표시되며, 방향이 적을수록 메모리도 적게 듭니다. 참고로 Sun Forge 쇼케이스의 기사는 애니메이션 4개에 스프라이트 968개이며, Windows, Mac, Linux용으로 패킹하면 81MiB를 차지합니다.
